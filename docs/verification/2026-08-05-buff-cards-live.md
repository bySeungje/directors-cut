# 강화 카드 라이브 실측 — 2026-08-05

환경: dev 서버(vite 8.2.0) + Chrome 자동화 탭, `http://localhost:5173/directors-cut/`
방식: `window.__setBuff(card)`로 카드를 강제 적용한 뒤 화면 밖(-500,-500 등)에 적을 스폰해 스탯을 직접 읽음. 플레이에 간섭하지 않도록 측정 후 즉시 비활성화.

## 1. 스탯 카드 — 스펙 §3.4.1 대조

| 카드 | chaser | shooter | splitter | elite chaser |
|---|---|---|---|---|
| `NONE` (기준) | HP 2 / 이속 90 | HP 3 / 60 | HP 3 / 75 | HP 6 / 103.5 |
| `TOUGH` | **3** / 90 | **4** / 60 | **4** / 75 | **7** / 103.5 |
| `SWIFT` | 2 / **112.5** | 3 / **75** | 3 / **93.75** | 6 / **129.37** |
| `RELENTLESS` | **1** / **130.5** | 3 / 60 | 3 / 75 | **5** / **150.07** |

- `TOUGH` 전 적 HP +1 ✅ / 이속 불변 ✅
- `SWIFT` 전 적 이속 ×1.25 ✅ (90→112.5, 60→75, 75→93.75) / HP 불변 ✅
- `RELENTLESS` **chaser에만** 적용 ✅ (shooter·splitter 완전 불변). 이속 ×1.45(90→130.5), HP −1
- **적용 순서 확인**: elite chaser 기준값 6 = 2×3(ELITE_HP_MULT), 여기에 `TOUGH`가 7로 **가산**됨 → 스펙의 "기본값 → elite 배수 → 강화 카드" 순서대로 동작. 배수가 아니라 +1이므로 elite에 과하게 얹히지 않는다.
- elite 이속도 중첩 확인: 103.5(=90×1.15) → `SWIFT` 129.37(×1.25), `RELENTLESS` 150.07(×1.45)

## 2. 동작 카드

| 항목 | `NONE` | 카드 적용 | 스펙 |
|---|---|---|---|
| 적탄 속도 (`MARKSMAN`) | 220 | **330** | ×1.5 ✅ |
| splitter 분열 소형 수 (`VOLATILE`) | 2기 | **3기** | 2→3 ✅ |

`RAPID_FIRE`(발사 간격 ×0.6)는 시간 기반이라 라이브 단발 측정으로는 판별이 어려워 유닛 테스트(`tests/buffs.test.ts`, `buffedFireInterval(1600)→960`)로 갈음했다. 호출부가 매 프레임 조회하는 것은 소스로 확인됨(`entities.ts` `updateShooter()`).

## 3. 누적 방지 — 핵심 방어선

`TOUGH` 적용 상태에서 chaser HP 3 확인 → 활성 적을 모두 제거해 웨이브 클리어 유도 → **직후 스폰한 chaser HP가 2로 복귀**. 카드가 다음 웨이브로 새지 않는다 ✅

`clearBuff()`가 `clearMutation()`의 `if (!state) return;` 가드 **앞**에 있어, mutation이 `NONE`인 웨이브(state가 null이라 early return)에서도 리셋이 실행된다 — 가드 뒤에 있었다면 변주 없는 웨이브마다 카드가 누적됐을 것이다.

## 4. 디렉터 연동

웨이브 클리어 후 폴백 디렉티브 수신 확인:
- `buff: "NONE"` — 뱅크 19항목 규약대로 ✅
- `mutation: "FOG"`, taunt 정상 출력, `fromLLM: false`(오프라인 폴백)
- `prevBuff`가 `directive.buff`로 갱신됨 ✅ — "직전과 같은 카드 금지" 판정의 입력이 살아 있다

## 5. 런타임 안정성

카드 6종을 순차 적용하며 프레임을 돌린 결과 60fps 유지, 콘솔 오류 0건, 적·탄환 풀 이상 없음.

## 주의 — 밸런싱 세션에서 알아둘 점

**`SWIFT`·`RELENTLESS`·`TOUGH`(스탯 계열)는 스폰 시점에 적용된다.** 웨이브 도중 `__setBuff`로 카드를 바꿔도 **이미 화면에 있는 적은 바뀌지 않고**, 그 이후 스폰되는 적부터 반영된다. 반면 `RAPID_FIRE`·`MARKSMAN`(발사 간격·유지거리·탄속)은 매 프레임 조회라 즉시 반영된다.

실제 게임에서는 웨이브 시작 전에 카드가 정해지므로 이 차이가 드러나지 않는다. 다만 `__setBuff`로 수동 테스트할 때는 카드를 바꾼 뒤 **다음 웨이브부터** 스탯 계열을 판단해야 한다.

## 자동화 환경 메모

Chrome 자동화 탭이 백그라운드면 `requestAnimationFrame`이 스로틀돼 게임 시간이 흐르지 않는다(적 속도 0으로 보임 — 회귀가 아님). `window.__game.loop.step(t)`를 16.666ms 간격으로 직접 호출해 프레임을 결정론적으로 전진시켜야 실제 동작을 관찰할 수 있다. 이 방식으로 chaser가 0.5초에 43px 접근(이속 90과 일치)함을 확인했다.
