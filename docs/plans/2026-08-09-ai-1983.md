## 0. 이 플랜이 지키는 것

**게임의 유일한 성공 조건은 소름이고, 소름은 순서에서 난다** — 관찰 → (1.2초, 아무 일도 안 일어남) 예고 → 다음 웨이브에 마커 0.6초 먼저 → 스폰 → 확인. 말이 먼저, 그림이 나중. 이 순서가 뒤집히면 같은 코드로도 실패다. 따라서 **CP3의 타이밍 파이프라인을 문장 UI보다 먼저 만든다.**

### 승제 확정 3건 (2026-08-10, 스펙 위에 얹음)
1. 재직자 보증·약관 확인 **완료** → `risk-terms-unchecked` 해소
2. `req-shared-memory`(교차 기억)를 **오늘 구현 범위로 승격** (should → 실질 must)
3. **배포 환경 단일화** — 로컬 테스트를 쓰지 않는다. 배포된 Pages에서 테스트·게이트 판정·영상 촬영·제출. 테스트한 것이 곧 제출물이 된다(배포본·HEAD·작업트리 분기 원천 차단). 대신 **push→Pages 반영 시간을 사이클마다 계상**한다.

### 허브 계약 (착수 전 필독 — 이번 작업이 정면으로 밟는 것들)
- `C-mutation-judge-collision` — 새 지표는 **변주 8종 각각과 교차 검사**. 변주가 지표를 강제하는 조합은 **판정 시점에 무효 처리**한다(예고 시점엔 못 거른다 — 변주는 예고 뒤에 정해진다).
- `C-zero-is-absence` — 0은 낮음이 아니라 데이터 없음. 하한 임계 지표에는 `> 0` 조건을 함께 건다.
- `C-player-needs-a-failure-axis` — 실패 축 없이 물량은 무의미. 이번 개정의 축은 **수동 사격** 하나다.
- `D-settlement-in-arena` — 정산은 인터벌 성적표가 아니라 **아레나 안 살아있는 미터 + 마지막 처치 시 스탬프**. 배수는 이 위에 얹는다.
- `C-threshold-hysteresis` / `C-metric-owner-check` — 임계 근처 뒤집힘, 지표가 누구를 재는지.

4. **12초 첫 관찰**(`req-first-observation-midwave`): 웨이브 1의 12초 지점에서 0.8초 정지 + 화면 중앙 관찰 문장 + 이동 히트맵. CP1에서 보존한 인터미션 패턴을 재사용.

   - **대응**: `null`일 때 침묵하지 말고 **데이터 없음 자체를 관찰로 말한다** — 예: `너는 아직 패턴을 안 만들었다. 계속 보겠다.` 그리고 12초 시점 전용 완화 임계를 별도로 두되, 완화 임계는 **판정(HIT/BROKEN)에는 쓰지 않는다**(판정은 기존 임계 유지 — 그러지 않으면 지표가 플레이어가 아니라 연출 요구를 재게 된다, `C-metric-owner-check`).

## 2. 컷 순서 (`req-cut-order`) — 시간 부족 시 이 순서로만 자른다

**자르는 순서**: ① 교차 기억(Supabase) → ② 역이용 보상 연출 → ③ 사망 화면 "너에게서 배운 것" → ④ 히트맵 오버레이 → ⑤ 판정 근거 상세 표시

**절대 자르지 않는 것**: 수동 사격 · 소름 5비트 순서 · 12초 첫 관찰 · 예고와 스폰의 인과 · 배수 정산 · 하네스 PASS · 제출 5종

**최저선**(`BR-MISSING-17`의 중의성 해소): 예고 없이 관찰만 있는 빌드는 제출하지 않는다. 13:00 게이트 ③④를 못 넘기면 **LLM 경로를 포기하고 예고·스폰을 엔진 결정론으로 스크립트 고정해서라도 5비트를 성립시킨다.** 즉 잘리는 것은 "예고"가 아니라 "예고를 LLM이 만든다"는 부분이다.
