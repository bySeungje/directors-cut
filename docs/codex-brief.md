# DIRECTOR'S CUT — 현행 진단 브리핑 (코덱스 인계용)

> 작성 2026-08-09. Playwright로 로컬 dev(`http://localhost:5173/directors-cut/`)를 실제 구동해
> 4런 플레이한 **실측 기반** 진단. 코드 읽기만으로 쓴 문서가 아니다.
> 스펙 SSOT는 `docs/specs/nan2026-prison-escape.md`, 계약 SSOT는 `src/contracts/directive.ts`.

---

## 1. 이 게임이 무엇인가

**수감자 734가 되어, 자신의 탈출 습관을 학습하는 AI 교도소장(DIRECTOR)의 감시망을 뚫고 7개 보안 구역을 빠져나가는 탑다운 스텔스 액션.**

- 스택: Phaser 4 + TypeScript + Vite. 960×640 고정 아레나, 구역(웨이브) 7개.
- 조작: WASD 이동 · Space 대시 · E/J 수동 EMP · **시안색 출구 원에 진입하면 구역 클리어**(전멸 불요).
- 스텔스 문법: 경비는 느리고(이속 92 vs 플레이어 220) 시야가 무섭다. 시야 콘은 **벽에 막히므로** 은신이 성립한다. 노출되면 발각 게이지가 차고, 만충 시 피해. 보안 무드는 clear→suspicious→searching→alert로 상승한다.
- **핵심 차별점 — AI 2층 구조:**
  - **결정론 엔진**: 시야 레이캐스트·발각 게이지·조사 행동·적응 순찰을 전부 로컬에서 계산. 좌표는 단 하나도 LLM이 만들지 않는다. LLM이 죽어도 게임은 100% 성립.
  - **LLM(claude-haiku-4-5, Supabase Edge Function `director`)**: 교도소장의 *판단과 목소리*만 담당 — 구역 구성·변주·카드·taunt·intent, 종료 시 WARDEN REPORT와 칭호. zod 검증 + 폴백 뱅크.
  - **적응 순찰**(`adaptPatrolRouteToLastRun`, ArenaScene.ts:853-875): 직전 구역 텔레메트리(히트맵 핫스팟·지배 사분면·벽붙기 비율)로 다음 구역 순찰 루트를 재구성.

**게임이 플레이어에게 하는 약속은 하나다: "네가 어떻게 빠져나갔는지 내가 보고 있고, 다음 구역은 그걸 노려 다시 짠다."**

## 2. 실측 결과 — 무슨 일이 실제로 벌어지는가

| 런 | 조작 | 결과 |
|---|---|---|
| 1 | 무입력 | 5.5초 사망 |
| 2 | 출구로 직진 | 7.7초 사망 (HP 5→0) |
| 3 | 스텔스 봇(발각 오르면 후퇴·내리면 전진) | 16.9초 사망 |
| 4 | 출구 정밀 접근 | **5.5초에 출구 도달 → 클리어 → 그 직후 4.3초간 맞다가 9.8초에 사망** |
| 5 | 무적(`__god`) | 1구역 68초 소요, 2구역 진입 성공 |

콘솔 로그가 4번 런의 정체를 확정한다 (2회 연속 동일 재현):

```
[ArenaScene] wave-cleared {wave: 1}     ← 1구역 클리어 성공
[habits] 웨이브 1 · 선택=없음 · 변주=NONE
[ArenaScene] player-died                 ← 클리어한 뒤에 죽음
[ArenaScene] LOSE
```

## 3. 문제 — 심각도 순

### P0-1. 성공이 곧 죽음이다 — 구역을 클리어하면 그 직후에 죽는다

출구 진입 → `wave-cleared` → `onWaveCleared`가 `clearStageRule()`(ArenaScene.ts:802-821, 호출 :1758)을 부른다. 이 함수는 **벽(`clearSectorMap`)·출구 존·시야 그래픽·보안 무드를 전부 지운다.** 그런데 **적 오브젝트와 피해 판정은 살아 있다.**

결과: 인터벌 동안 플레이어는 (a) 벽이 없어 은신 불가, (b) 출구 표시가 사라져 성공했는지도 모름, (c) 위치가 고정된 채 발각 게이지가 계속 차오름 → HP 4에서 0까지 4.3초 만에 소진.

스크린샷 증거: 클리어 직후 화면은 **벽도 출구도 없는 빈 격자에 적 무리와 HP 1**만 남는다.

> 플레이어 체감: "출구에 닿았는데 왜 죽지?" — 성공 피드백이 전무하므로 클리어한 사실조차 인지되지 않는다. **게임의 보상 구조가 뒤집혀 있다.** 이것 하나로 게임 전체가 성립하지 않는다.

**고칠 것**: 클리어 인터벌 진입 시 적 비활성화 또는 무적 부여, 그리고 명시적 성공 연출(현재 `EXIT ROUTE OPEN` 플래시는 있으나 즉시 clear에 묻힘). 클리어 순간 벽을 지우는 순서 자체를 재검토.

### P0-2. 보이지 않는 곳에서 발각된다 — 스텔스의 기본 계약 위반

- 화면에 그려지는 감지 콘: **range 160 / FOV 74°** (ArenaScene.ts:1573-1575)
- 실제 경비가 추격을 시작하는 시야: **range 215 / FOV 92°** (entities.ts:90-91)

플레이어에게 보여준 위험 범위보다 실제 위험 범위가 **34% 넓다.** 안전해 보이는 위치에서 들킨다.

추가로 "수색"이 사실상 실시간 완전 추적이다. `processVisionContact`(ArenaScene.ts:1448)가 마지막 목격 지점이 아니라 **매 프레임 플레이어 현재 좌표**를 조사 지점으로 갱신하고, 의심 0.34(약 0.55초 노출)를 넘으면 `raiseSecurityNetwork`가 **활성 적 전원**에게 강제 경보를 건다. 한 명이 0.55초 보면 8명이 전부 실좌표로 호밍한다.

> 플레이어 체감: "왜 들켰는지 모르겠고, 한 번 들키면 리커버리가 없다."

### P0-3. 1구역이 튜토리얼이 아니다 — 출구가 적 대열 한복판에 있다

- `spawn:'E'`의 좌표 공식(waveRunner.ts:76)은 **x를 1000으로 고정하고 y만 난수**로 뽑는다 → 8명이 동쪽 끝에 세로 일렬. 이건 의도된 대열이 아니라 공식의 부산물이다.
- 그런데 SECTOR 1의 출구도 동쪽 (858,92)이다. **스폰 코드는 `layout.exit`를 전혀 참조하지 않는다** — 충돌 검사가 아예 없다.
- 커밋 `3de0640`이 "시작점에 안 붙게" 하려고 `RING`→`E`로 옮기면서 문제를 시작점에서 출구로 이동시켰고, 수량도 7→8로 늘렸다.
- 순찰 루트 1(ArenaScene.ts:106)의 웨이포인트 (835,112)는 출구에서 **30px** 거리다. 여기에 3명이 배정된다.
- **출구 앞 마지막 ~280px는 벽이 0개인 개활지.** rack·crate·pipe 같은 프롭은 `SECTOR_PROPS`로 **그래픽만 그려질 뿐 시야를 막지 않는다**(물리/레이캐스트 대상은 `SECTOR_LAYOUTS[n].walls`뿐).
- 탐지 수치(발각 0.56/s, 감쇠 0.38/s, 유예 1.4초)는 **최종 구역과 완전히 동일**하다. 1구역 완화는 "룰 없음·센서 없음·변주 없음" 세 가지뿐.

> 플레이어 체감: "숨을 곳으로 보이는 것들이 실제로는 안 가려주고, 출구 앞은 뚫을 방법이 없다."

### P1. 핵심 컨셉이 화면에 존재하지 않는다

적응 로직은 **실제로 크게 작동한다** — 웨이포인트 이동량 중앙값 354px(맵 폭의 37%), 2구역부터 예외 없이 발동, shooter/splitter는 설계 루트를 통째로 버리고 직전 핫스팟 주위 삼각 루프로 대체된다. 문제는 그게 **플레이어에게 전달되지 않는다**는 것이다.

- 귀속 신호의 전부: **10px 폰트로 좌상단에 2.6초 뜨는 로그 한 줄**(`이전 동선 분석: NW 반복 이동 · 순찰 루트 재배치`)과 alpha 0.18의 정적인 붉은 원. 2.6초 안에 의심도가 오르면 그 로그마저 덮인다.
- 구역 소개 문구(`SECTOR_STORIES`, ArenaScene.ts:207-250)는 **구역 번호로 하드코딩**되어 텔레메트리를 전혀 참조하지 않는다. 5구역은 "네가 반복한 적재 경로를 소각 라인으로 바꿨다"고 말하지만, 그 `HOTSPOT_LOCKDOWN` 룰은 배너 1회가 전부이고 `updateStageRule`에서 `break`만 한다 — **문구가 약속하는 메커닉이 구현돼 있지 않다.**
- LLM taunt/intent는 순찰 적응을 **구조적으로 모른다.** 엣지 함수 프롬프트에 순찰 루트·핫스팟 개념 자체가 없어서, taunt가 루트 변경을 지목하는 일이 원리적으로 불가능하다.
- 경로 프리뷰·히트맵 오버레이·"DIRECTOR가 X를 학습했다" 자막 — **전부 없음.**
- 사망 후 R 재시작하면 `waveLogs`·`lastHotspot`이 초기화된다(저장소 없음). **"AI가 나를 계속 지켜본다"는 서사가 런을 넘어 이어지지 않는다.**

### P1-2. 구조적 문제 — 약속이 실현되는 지점에 플레이어가 도달하지 못한다

"AI가 학습한다"는 정의상 **2구역부터** 나타난다(1구역은 직전 로그가 없어 적응 자체가 없다). 그런데 1구역에서 5~17초 만에 죽고, 클리어해도 P0-1로 죽는다. 무적으로도 68초가 걸렸다.

**심사위원이 30초를 플레이하면 이 게임의 핵심을 한 번도 보지 못한다.** 이것이 "이게 아니다"라는 감각의 가장 깊은 원인일 가능성이 높다.

## 4. 권장 작업 순서

1. **P0-1 클리어 인터벌 무적화/적 정지** — 이걸 고치기 전에는 어떤 밸런싱도 의미가 없다. 승리를 승리로 만드는 것이 최우선.
2. **P0-2 시야 일치** — 그려지는 콘과 실제 추격 반경을 같은 상수로 묶는다. 스텔스는 "보이는 위험이 전부"라는 계약 위에서만 성립한다.
3. **P0-3 1구역 재배치** — 스폰 시 `layout.exit`에서 최소 거리 확보, 출구 접근로에 엄폐 벽 추가(또는 프롭을 실제 차폐물로 승격), 1구역 탐지 수치 완화.
4. **P1 적응 가시화** — 구역 진입 시 "직전 런에서 읽은 습관 → 이번 구역의 대응"을 **크게, 오래** 보여준다. 가능하면 이전 순찰 루트와 새 루트를 겹쳐 보여주는 1~2초 연출. 하드코딩 문구를 텔레메트리 기반 동적 문구로 교체.
5. 구현 없는 `HOTSPOT_LOCKDOWN` 룰을 구현하거나, 그 문구를 실제 동작에 맞게 수정.

## 5. 작업 규약 (반드시 지킬 것)

- 하네스: `bash scripts/ai_harness.sh --fast`(tsc+vitest) / `--full`(+build) → `HARNESS RESULT: PASS|FAIL`
- 계약 변경 시 `src/contracts/directive.ts`와 `supabase/functions/director/index.ts`의 `DIRECTIVE_JSON_SCHEMA` 수동 사본을 **함께** 갱신
- 프록시 배포는 맥북 전용(`--no-verify-jwt` 필수). 로컬 dev는 CORS로 LLM이 항상 폴백 경로 → 폴백 QA 겸용
- 재현용 dev 훅: `window.__game`, `window.__god = true`, `window.__skipWave()`
  - ⚠️ `__skipWave()`는 현재 무력하다 — 적 전멸 처리만 하는데 클리어 조건은 `exitReached`라서 넘어가지 않는다. QA 훅도 함께 고칠 것.
