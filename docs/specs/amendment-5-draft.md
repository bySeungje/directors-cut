## 0. 왜 바꾸는가

현행은 **디렉터만 전략 게임을 하고 플레이어는 반사신경 게임을 한다.** 디렉터는 구성·변주·강화·봉인 4개 레버로 판을 짜는데, 플레이어의 라운드 간 결정은 무작위 3장에서 스탯을 고르는 추첨이다. 두 층의 깊이가 다르고, 얕은 쪽이 플레이어 몫이다 — 이것이 "흔해빠졌다"의 정체다.

전환 후에는 **양측이 같은 종류의 결정을 한다.** 디렉터가 다음 판을 선포하고, 플레이어가 그걸 보고 카운터를 고르고, 웨이브가 자동 해결된다. 플레이어의 손이 아니라 플레이어의 **판단**이 승부를 가른다.

## 1. 선행 결함 수정 (Phase 0 — 전환과 무관하게 필요)

**디렉터는 예산을 다 쓴 적이 없다.** 이것을 고치지 않으면 전환 후에도 판이 비어 있다 — 조작이 없으므로 오히려 더 치명적이다.

- `src/director/validator.ts:33` — 예산 검사가 상한뿐이다(`total > budgetFor(wave)` → null). 하한이 없어 예산 90에 20을 써도 통과한다.
- `supabase/functions/director/index.ts:46` — "총 비용은 **예산 이하로**" (채우라는 지시가 없다)
- `supabase/functions/director/index.ts:50` — "**물량으로 압살하지 마라**" — 프로젝트 실측이 "위협은 동시 접촉 개체 수가 만든다"고 결론냈으므로, 이 문장은 **유일하게 작동하는 위협 레버를 금지**한다.

폴백 뱅크 웨이브 7은 84점을 꽉 채워 쓴다(30+30 chaser + 12 shooter = 72기). 8/6 밸런스 실측은 전부 이 뱅크 경로에서 나왔고, LLM 경로에는 한 번도 적용된 적이 없다. **측정치와 승제 체감이 어긋난 이유가 이것이다.**

**수정:** 예산 하한 도입(예산의 80% 미만 → 폴백), 프롬프트 2줄 교체("예산을 채워라" / "압살 금지" 삭제). 관련 유닛테스트 추가.

## 2. 새 코어 루프

```
① 디렉터 선포 (인터벌 전반)
   다음 웨이브의 구성·강화 카드·변주를 플레이어에게 공개한다.
   지금은 L키 디버그 패널 뒤에 숨어 있는 정보를 본편으로 승격하는 것이다.
   대사(taunt)는 그대로 타이핑 연출.

② 플레이어 카운터 드래프트 (인터벌 후반)
   3장 중 1장. 각 카드는 { 전술 1종 + 업그레이드 1종 } 묶음이다.
   업그레이드 축을 남기는 이유: UPGRADE_IDS를 건드리면 DENY_TARGETS 드리프트
   가드(tests/upgrades.test.ts:66)가 계약→프록시 수동 사본→수동 배포까지
   사슬을 끌고 나온다. deny(봉인)도 업그레이드 축에 계속 걸린다.

③ 웨이브 자동 해결 (관전)
   플레이어 입력 없음. 선택한 전술이 이동 정책을 결정한다.
   자동 조준·자동 사격은 지금 그대로(이미 구현돼 있다).
   전투 구간에만 배속을 걸어 관전 시간을 압축한다.

④ 텔레메트리 → 디렉터
   기존 WaveLog에 `tactic` 필드 1개 추가. 디렉터는 플레이어가 어떤 전술을
   반복하는지 읽고 다음 판을 짠다.
```

## 3. 전술 어휘 (4종)

이동 방식이 아니라 **교전 태세**로 잡는다. 실측된 결과 격차(같은 chaser 80기에서 정지 26 대 이동 1 — 26배)는 "정지 vs 이동" 이분법에서 나온 값이라, 후보가 전부 "움직임"이면 결과가 붙어 드래프트가 무의미해진다.

| 전술 | 행동 | 강함 | 약함 |
|---|---|---|---|
| `ORBIT` 선회 | 아레나 외곽을 따라 계속 돈다 | chaser 물량 — 접촉을 계속 흘린다 | shooter — 예측 가능한 궤도가 조준탄에 노출 |
| `HOLD` 고수 | 중앙 유지, 자동조준 가동률 최대 | 소수 elite — 화력을 한 점에 모은다 | 물량 — 동시 접촉이 그대로 들어온다 |
| `BREAK` 돌파 | 가장 밀집한 무리로 돌진, 대시 무적 활용 | `ENCIRCLE` — 조여들기 전에 링을 뚫는다 | 용암 변주 — 경로를 무시하고 밟는다 |
| `BAIT` 유인 | 한쪽으로 몰았다가 대시로 빠져나감 | chaser 직진 추격 — 뭉쳐서 흘린다 | `INTERCEPT` — 예측 요격에 정확히 걸린다 |

**디렉터의 기존 어휘가 그대로 카운터 축이 된다.** 새 enum도, 계약 변경도 없다.

## 4. 권한 경계 (§3.4 원칙 유지 — 확장 아님)

- LLM은 **플레이어에게 제시되는 카드의 텍스트·라벨·효과를 생성하지 않는다.** 카드 풀과 문구는 엔진 상수다.
- LLM은 **어떤 수치도 정하지 않는다.** 전술의 효과·비용·좌표는 전부 엔진 계산.
- **플레이어 자유 텍스트 입력을 도입하지 않는다.** 현재 프롬프트 인젝션 표면이 닫혀 있고(자유 입력 0·canvas 렌더·HTML 싱크 없음), 마감 3일 전에 입력 검증을 새로 설계할 여유가 없다.
- `Directive` 계약(zod·`DIRECTIVE_JSON_SCHEMA`·프록시 수동 사본)은 **동결**한다. `WaveLog.tactic`만 추가 — 순수 TS 인터페이스라 검증기·폴백 뱅크·유닛테스트 어느 것도 반응하지 않는다.

## 5. 폴백 — 결정론 카운터가 LLM보다 먼저

현행 `pickFallback(wave, prevMutation)`은 플레이어의 수를 입력으로 받지 않는다. 대칭 구조에서 LLM이 실패하면 폴백이 **동문서답**을 하고, 하필 게임의 존재 이유가 시연되는 순간에 그것이 보인다("플레이어는 폴백을 눈치채지 못한다"는 §3.4 불변식이 깨진다).

**따라서 LLM 카운터보다 결정론 카운터 표를 먼저 만든다.** 뱅크 선택에 `prevTactic`을 추가해, 플레이어의 직전 전술을 카운터하는 항목을 고른다. LLM은 그 위에서 선택을 다양화하고 이유를 말하는 층이다. **이 표를 못 만들면 전환을 접는다**(§7 게이트 G1).

## 6. 관전 가능성

무조작 웨이브 40초는 "참신함"이 아니라 "미완성"으로 읽힐 수 있다. 전투 구간에 `timeScale` 배속을 걸어 압축하고, 인터벌(드래프트)은 실시간으로 둔다. 배속 값은 실플레이로 정한다.

## 8. 알려진 리스크 (심의에서 확인된 것)

1. **[critical] 산출물 미완주 = 심사 제외.** 공고는 5개 항목 전부 제출을 요구하고 하나라도 누락 시 심사 제외다. 하방이 감점이 아니라 0이다. → G1·G2 게이트가 유일한 방어선.
2. **[high] 새 코어 루프는 플레이테스트 이력이 0.** 이 repo에서 8/6에 루프를 건드린 변경 4건이 4건 모두 실측 후 재설계를 요구했다. 교정 라운드 1회는 확률적으로 확정이고 견적에 포함해야 한다.
3. **[high] 견적 정규화.** 기술 리뷰 9~15h는 교정 1회·산출물 제외 기준이다. 이 repo의 교정 기저율(4/4)과 산출물(5~8h)을 되넣으면 26~37h이고, 가용 시간은 25~28h다. **정상 시나리오에서 창을 넘긴다** — G1이 형식이 아니라 실제로 작동해야 하는 이유다.
4. **[medium] "왜 LLM인가" 질문.** 카운터 드래프트 구조 자체는 상성 표로도 성립한다(게임잼 24시간·생성형 AI 미사용 선례 존재). 대응: LLM의 몫을 **행동 텔레메트리의 자연어 독해**로 명시하고, 그것이 화면과 문서에 보이게 한다.
5. **[medium] 문서 드리프트.** 조작 방식이 `TitleScene.ts`·스펙 §3.1·PDF 2종 4표면에서 동시에 거짓이 된다. `게임소개.pdf`는 이미 8/5자로 8/6 amendment 2건보다 낡아 있어 어느 경로에서도 갱신 대상이다.
6. **[medium] 세션 호출 캡.** 현재 런당 8콜(세션 산입 7), 캡 20 → 페이지 로드당 2.8런. 라운드당 호출을 늘리지 않는 설계를 유지한다(카운터는 기존 디렉티브 호출 1회에 포함).

## 9. 완료 기준 (검증 리포트에서 ✅/❌ 대조)

1. 웨이브 1→7 완주에 게임플레이 키 입력이 0회다.
2. 인터벌에서 다음 웨이브의 구성·강화·변주가 플레이어에게 **글로** 보인다.
3. 같은 웨이브 구성에 대해 전술 4종의 결과(잃은 체력)가 유의미하게 갈린다 — 최선과 최악의 차이가 체력 2칸 이상.
4. LLM을 끊어도(프록시 차단) 폴백이 플레이어의 직전 전술을 카운터한다.
5. 디렉터가 웨이브 예산의 80% 이상을 실제로 소비한다(유닛 테스트 + 라이브 1런 확인).
6. 하네스 `--full` PASS.
