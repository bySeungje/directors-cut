**심사 서사(이 게임의 존재 이유):** NAN 2026은 "AI의 다음 단계를 설계할 디렉터"를 찾는다. 이 제출물은 그 문장을 이중으로 되돌려준다 — ① 게임 안에 플레이어를 읽고 판을 설계하는 AI 디렉터가 있다. ② 이 게임 자체가 AI 디렉팅(스펙→플랜→구현→검증 파이프라인)으로 만들어졌고, 그 과정이 repo와 기술 문서에 남아 있다.

**플랫폼:** 웹 (데스크톱 브라우저 우선). GitHub Pages 배포, 링크 클릭 즉시 플레이. 로그인·설치·유료 라이선스 없음.

## 3. 게임 디자인

### 3.1 코어 루프 (1판 ≈ 6분)

1. **웨이브 전투 (~40초):** 탑다운 단일 아레나. WASD 이동, 가장 가까운 적 자동 조준 사격, Space 대시(무적 프레임 0.3초, 쿨다운 2초). 적 전멸 시 클리어.
2. **디렉터 인터벌 (~8초):** 플레이 로그 → LLM → 디렉티브(다음 웨이브 구성 + 규칙 변주 1개 + 도발 대사). 대사가 타이핑 연출로 표시된 뒤 변주가 실제 적용된다. 웨이브 1은 고정 오프닝 구성(로그가 아직 없음) — 디렉터는 웨이브 1 종료 후부터 개입한다(런당 디렉티브 6회 + 리포트 1회 = 호출 7회).
3. **업그레이드 3택 1:** 인터벌 중 선택. 디렉터의 다음 대사·설계는 내 빌드 선택도 참조한다.
4. **승리 = 7웨이브 클리어(디렉터 격파). 패배 = HP 0.** 어느 쪽이든 디렉터가 쓴 **플레이 분석 리포트**(≈400자 + 칭호)로 끝난다. 리스타트 1클릭.

### 3.2 플레이어

- HP 5칸, 피격 시 1칸 + 무적 1초. 이동속도·연사·탄속·데미지는 업그레이드로 성장.
- 업그레이드 풀(8종, 매 인터벌 무작위 3 제시): 데미지+, 연사+, 이속+, HP+1(즉시회복 포함), 관통, 멀티샷, 탄속+, 대시 쿨다운−.

### 3.3 적 (3종 + 엘리트 플래그)

| 타입 | 형태 | 행동 |
|---|---|---|
| chaser | 삼각 | 플레이어 직진 추격 |
| shooter | 사각 | 거리 유지 + 조준탄 발사 |
| splitter | 육각 | 사망 시 소형 2기로 분열 |

- elite: HP×3·크기↑·이속 소폭↑·발광. 디렉터가 부여.
- 적 성능은 고정이 아니다 — 디렉터가 웨이브마다 **강화 카드** 1장으로 스탯을 조정한다(§3.4.1).

### 3.4 디렉터 — 권한 경계 (핵심 설계)

**원칙: LLM에게는 어휘를, 실행은 결정론으로.** 디렉터 출력은 자유 텍스트/코드가 아니라 아래 JSON 어휘로 제한된다. 창의성은 조합과 언어에서, 안정성은 스키마 검증과 예산 규칙에서 나온다.

**입력 — 플레이 로그(웨이브 종료마다 집계):**
```json
{
  "wave": 2, "clearTimeSec": 34.2, "hpLost": 2,
  "damageSources": {"chaser": 1, "shooter": 1},
  "movement": {"quadrantTime": {"NW": 0.4, "NE": 0.1, "SW": 0.4, "SE": 0.1},
               "wallHugRatio": 0.55, "dashCount": 6},
  "combat": {"kills": {"chaser": 12, "shooter": 3, "splitter": 2}, "accuracy": 0.61},
  "upgrades": ["DAMAGE_UP", "MOVE_SPEED_UP"],
  "prevMutations": ["FOG"]
}
```

**출력 — 디렉티브:**
```json
{
  "composition": [
    {"type": "chaser|shooter|splitter", "count": 1, "spawn": "N|S|E|W|RING|PINCER|BEHIND", "elite": false}
  ],
  "mutation": "NONE|LAVA_LEFT|LAVA_RIGHT|FOG|SPEED_SURGE|SHRINK_ARENA|SPAWN_STORM",
  "taunt": "≤60자 — 로그의 실제 습관을 반드시 1개 지목",
  "intent": "≤100자 설계 의도(리포트·디렉터 로그 패널용)"
}
```

**안전 규칙(엔진 측 검증, 위반 시 폴백):**
- 스키마 검증(zod). 필드 누락·enum 밖 값·문자열 길이 초과 → 거부.
- **포인트 예산:** 웨이브 n의 총 스폰 비용 상한 = f(n) (chaser 1·shooter 2·splitter 2, elite ×3). 난이도 곡선을 LLM이 깨뜨릴 수 없다.
- 동일 mutation 2연속 금지(엔진이 강제 교체).
- 응답 4초 초과·오류·검증 실패 → **사전 제작 디렉티브 뱅크**(웨이브별 3종 × 7)에서 무작위 폴백. 대사도 뱅크에 포함 — 플레이어는 폴백을 눈치채지 못한다.

**엔드게임 리포트:** 별도 호출 1회. 전체 런 요약 입력 → 400자 내외 분석 + 칭호(예: "벽면 곡예사"). 실패 시 정적 템플릿 폴백.

### 3.4.1 강화 카드 — 적 성능 표적 조정 *(amendment 2026-08-05, 승제 승인)*

디렉터는 적 **구성**뿐 아니라 적 **성능**도 조정한다. 플레이어가 잘하는 축을 골라 그 축을 무력화하는 것이 목적이다.

**어휘**: `buff` 필드 1개 — 아래 7종 enum 중 하나. 수치는 LLM이 정하지 못한다(권한 경계 원칙 유지).

| 카드 | 효과 | 노리는 습관(로그 지표) |
|---|---|---|
| `NONE` | 없음 | — |
| `TOUGH` | 전 적 HP +1 (분열 소형 제외 — 소형은 항상 HP 1) | 명중률 높음 (`combat.accuracy`) |
| `SWIFT` | 전 적 이속 +25% | 거리를 벌리며 지연 (`clearTimeSec` 김) |
| `RELENTLESS` | chaser 이속 +45%, chaser HP −1(최소 1) | 대시 남용 (`movement.dashCount`) |
| `RAPID_FIRE` | shooter 발사 간격 ×0.6 (1600→960ms) | 탄을 잘 피함 (`hpLost` 낮음) |
| `MARKSMAN` | shooter 탄속 +50%, 유지거리 +80 (260→340) | 원거리 안전지대 사용 (`wallHugRatio` 낮음) |
| `VOLATILE` | splitter 분열 소형 2→3기 | 물량 처리 능숙 (`combat.kills.splitter`) |

**적용 순서**: `ENEMY_DEF` 기본값 → elite 배수 → 강화 카드. 단 splitter 분열 소형은 `hpOverride: 1`로 스폰되어 HP 버프를 받지 않는다(이속 버프는 받는다). 카드 비용을 소형까지 강화되는 것을 전제로 매기지 않았고, 걸리면 splitter 중심 웨이브의 난이도가 급등하기 때문이다 — 2026-08-05 전체 리뷰에서 확인·의도로 확정. 예) elite chaser HP = 2×3=6, `TOUGH` 적용 시 7. 이속은 elite 1.15 × `SWIFT` 1.25 = 1.4375배.

**밸런스 규칙 (검증 계층이 강제, 위반 시 폴백)**:
1. **웨이브당 1장.** 웨이브 1(오프닝)은 항상 `NONE`.
2. **비용 = 해당 웨이브 예산의 25%(반올림)**, `NONE`은 0. 예산 총액에 합산되므로 강화하면 물량이 줄어든다 — 자동 트레이드오프.
3. **직전 웨이브와 동일한 카드 금지**(`NONE` 제외). 동일 시 `NONE`으로 강제 교체 — mutation과 같은 규칙.
4. **웨이브 종료 시 초기화.** 절대 누적되지 않는다 — 누적이 밸런스 폭주의 주원인이다.
5. 폴백 뱅크 19항목은 전부 `NONE`이다. 폴백은 "디렉터의 판단이 부재한 상태"이므로 강화 없음이 의미론적으로도 맞고, 기존 예산 검증을 건드리지 않는다.

**설계 의도**: `RELENTLESS`처럼 **강해지는 대신 약해지는 축**을 섞는다. 압박은 커지되 클리어 불가능해지지 않게 하는 장치다.

**시스템 프롬프트**: 위 카드↔지표 대응표를 프롬프트에 넣어, 디렉터가 로그에서 관찰된 강점을 근거로 카드를 고르고 `intent`에 그 이유를 쓰게 한다. taunt도 그 강점을 지목해야 한다.

**워밍업 호출** *(amendment 2026-08-05 — 승제 승인)*: 타이틀 화면 진입 시 프록시에 디렉티브 요청 1회를 미리 발사한다. 응답은 버린다.
- **이유**: 하루 첫 호출은 API의 최초 스키마 컴파일 비용과 Edge Function 콜드스타트가 겹쳐 4초 타임아웃을 넘길 확률이 높다. 하필 그 호출이 웨이브 1→2 인터벌 — 게임의 핵심(디렉터가 내 플레이를 읽는 첫 순간)이라, 심사자가 한 판만 플레이하면 LLM 경로를 한 번도 보지 못할 수 있다.
- **동작**: 타이틀에서 비동기 발사 후 결과를 기다리지 않는다(플레이어는 즉시 시작 가능). 실패해도 무시 — 게임 흐름에 어떤 영향도 주지 않는다.
- **캡**: 워밍업은 세션 호출 상한(20)에 **산입하지 않는다**. 일일 예산 캡에는 산입한다.
- 4초 타임아웃 값 자체는 변경하지 않는다.

## 4. 아키텍처

- **클라이언트:** Phaser 4 + TypeScript + Vite. *(표기 정정 2026-08-05: 설치·검증된 실버전은 Phaser 4.x — 초안의 "Phaser 3"는 표기 오류)* 정적 빌드 → GitHub Actions로 Pages 배포(push 시 자동). 프론트에 API 키 없음.
- **프록시:** Supabase Edge Function `director` 1개. 역할: Anthropic API 호출(모델 claude-haiku-4-5, max_tokens 제한), 시스템 프롬프트·어휘 정의 서버측 보관, **세션당 호출 상한 20회(약 3런 분량, 초과 시 무음 폴백) + 일일 예산 캡(값은 플랜에서 확정)**, CORS는 Pages 도메인만 허용. 구현 시 `claude-api` 스킬 로드 후 최신 모델·파라미터 확정.
- **모듈 경계:** `engine`(Phaser 씬·엔티티·웨이브 실행기 — 디렉티브만 소비) / `telemetry`(로그 집계) / `director-client`(프록시 호출·검증·폴백 뱅크) / `ui`(인터벌·리포트). engine은 director-client의 내부를 모른다 — 디렉티브 스키마가 유일한 계약(contract-first).
- **테스트·하네스:** `scripts/ai_harness.sh` (HARNESS_CONTRACT 규약: `--fast` = tsc+lint+unit, `--full` = +빌드). 유닛 대상: 디렉티브 검증기·예산 규칙·폴백 선택기·로그 집계기(전투 로직은 수동 플레이 검증).

## 5. 완료 기준 (검증 리포트에서 ✅/❌ 대조)

1. GitHub Pages URL 접속 → 클릭 1회로 플레이 시작, 초기 로드 3초 이내(일반 회선).
2. 7웨이브 완주·사망 양 경로 모두 리포트 표시 + 리스타트 동작.
