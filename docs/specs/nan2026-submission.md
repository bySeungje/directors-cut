## 1. 개요

**한 줄:** 당신의 플레이를 읽고 판을 다시 짜는 AI 디렉터와 7웨이브 동안 싸우는 웹 미니 서바이벌.

**심사 서사(이 게임의 존재 이유):** NAN 2026은 "AI의 다음 단계를 설계할 디렉터"를 찾는다. 이 제출물은 그 문장을 이중으로 되돌려준다 — ① 게임 안에 플레이어를 읽고 판을 설계하는 AI 디렉터가 있다. ② 이 게임 자체가 AI 디렉팅(스펙→플랜→구현→검증 파이프라인)으로 만들어졌고, 그 과정이 repo와 기술 문서에 남아 있다.

**플랫폼:** 웹 (데스크톱 브라우저 우선). GitHub Pages 배포, 링크 클릭 즉시 플레이. 로그인·설치·유료 라이선스 없음.

## 3. 게임 디자인

### 3.1 코어 루프 (1판 ≈ 6분)

1. **웨이브 전투 (~40초):** 탑다운 단일 아레나. WASD 이동, 가장 가까운 적 자동 조준 사격, Space 대시(무적 프레임 0.3초, 쿨다운 2초). 적 전멸 시 클리어.
2. **디렉터 인터벌 (~8초):** 플레이 로그 → LLM → 디렉티브(다음 웨이브 구성 + 규칙 변주 1개 + 도발 대사). 대사가 타이핑 연출로 표시된 뒤 변주가 실제 적용된다. 웨이브 1은 고정 오프닝 구성(로그가 아직 없음) — 디렉터는 웨이브 1 종료 후부터 개입한다(런당 디렉티브 6회 + 리포트 1회 = 호출 7회).
3. **업그레이드 3택 1:** 인터벌 중 선택. 디렉터의 다음 대사·설계는 내 빌드 선택도 참조한다.
4. **승리 = 7웨이브 클리어(디렉터 격파). 패배 = HP 0.** 어느 쪽이든 디렉터가 쓴 **플레이 분석 리포트**(≈400자 + 칭호)로 끝난다. 리스타트 1클릭.

### 3.2 플레이어

- HP 5칸, 피격 시 1칸 + 무적 1초. 이동속도·연사·탄속·데미지는 업그레이드로 성장.
- 업그레이드 풀(8종, 매 인터벌 무작위 3 제시): 데미지+, 연사+, 이속+, HP+1(즉시회복 포함), 관통, 멀티샷, 탄속+, 대시 쿨다운−.

### 3.3 적 (3종 + 엘리트 플래그)

| 타입 | 형태 | 행동 |
|---|---|---|
| chaser | 삼각 | 플레이어 직진 추격 (디렉터가 행동 카드로 예측 요격·포위로 바꿀 수 있다 — §3.4.2) |
| shooter | 사각 | 거리 유지 + 조준탄 발사 |
| splitter | 육각 | 사망 시 소형 2기로 분열 |

- elite: HP×3·크기↑·이속 소폭↑·발광. 디렉터가 부여.
- 적 성능은 고정이 아니다 — 디렉터가 웨이브마다 **강화 카드** 1장으로 스탯을 조정한다(§3.4.1).

### 3.4 디렉터 — 권한 경계 (핵심 설계)

**원칙: LLM에게는 어휘를, 실행은 결정론으로.** 디렉터 출력은 자유 텍스트/코드가 아니라 아래 JSON 어휘로 제한된다. 창의성은 조합과 언어에서, 안정성은 스키마 검증과 예산 규칙에서 나온다.

**입력 — 플레이 로그(웨이브 종료마다 집계):**
```json
{
  "wave": 2, "clearTimeSec": 34.2, "hpLost": 2,
  "damageSources": {"chaser": 1, "shooter": 1},
  "movement": {"quadrantTime": {"NW": 0.4, "NE": 0.1, "SW": 0.4, "SE": 0.1},
               "wallHugRatio": 0.55, "dashCount": 6, "hotspotConcentration": 0.31},
  "combat": {"kills": {"chaser": 12, "shooter": 3, "splitter": 2}, "accuracy": 0.61,
             "clusterRatio": 0.22},
  "upgrades": ["DAMAGE_UP", "MOVE_SPEED_UP"],
  "prevMutations": ["FOG"]
}
```

**출력 — 디렉티브:**
```json
{
  "composition": [
    {"type": "chaser|shooter|splitter", "count": 1, "spawn": "N|S|E|W|RING|PINCER|BEHIND", "elite": false}
  ],
  "mutation": "NONE|LAVA_LEFT|LAVA_RIGHT|LAVA_HOTSPOT|FOG|SPEED_SURGE|SHRINK_ARENA|SPAWN_STORM",
  "buff": "NONE|TOUGH|SWIFT|RELENTLESS|RAPID_FIRE|MARKSMAN|VOLATILE|INTERCEPT|ENCIRCLE|EVASIVE",
  "deny": "NONE|DAMAGE_UP|FIRE_RATE_UP|MOVE_SPEED_UP|HP_PLUS|PIERCE|MULTI_SHOT|BULLET_SPEED_UP|DASH_CD_DOWN",
  "taunt": "≤60자 — 로그의 실제 습관을 반드시 1개 지목",
  "intent": "≤100자 설계 의도(리포트·디렉터 로그 패널용)"
}
```

**안전 규칙(엔진 측 검증, 위반 시 폴백):**
- 스키마 검증(zod). 필드 누락·enum 밖 값·문자열 길이 초과 → 거부.
- **포인트 예산:** 웨이브 n의 총 스폰 비용 상한 = `8 + n×4 + max(0, n−4)² × 6` (chaser 1·shooter 2·splitter 2, elite ×3). 난이도 곡선을 LLM이 깨뜨릴 수 없다.
  - 웨이브별: 12 / 16 / 20 / 24 / **34 / 56 / 90**. 후반이 제곱으로 가속하는 이유는 **플레이어 성장이 곱셈이기 때문**이다 — 업그레이드 6회면 초당 피해가 3.6에서 44.5로 12배가 된다(§3.4.3).
  - **임계점은 개체 수다**(2026-08-06 실측). 강한 빌드가 가만히 서 있을 때 chaser 60기는 체력 1을 깎지만 80기는 26을 깎는다. 반면 elite chaser 40기는 총 체력이 더 많은데도 2밖에 못 깎는다 — 위협은 총 체력이 아니라 **동시에 접촉하는 개체 수**가 만든다. 최종 웨이브를 그 임계점(chaser 환산 90) 위에 두되, 100 이상의 즉사 구간은 피한다.
  - 같은 규모에서 **움직이면 체력 1**만 잃는다. 즉 이 곡선은 "가만히 있으면 죽고 움직이면 산다"를 만든다.
- 동일 mutation 2연속 금지(엔진이 강제 교체).
- 응답 4초 초과·오류·검증 실패 → **사전 제작 디렉티브 뱅크**(웨이브별 3종 × 7)에서 무작위 폴백. 대사도 뱅크에 포함 — 플레이어는 폴백을 눈치채지 못한다.

**엔드게임 리포트:** 별도 호출 1회. 전체 런 요약 입력 → 400자 내외 분석 + 칭호(예: "벽면 곡예사"). 실패 시 정적 템플릿 폴백.

### 3.4.1 강화 카드 — 적 성능 표적 조정 *(amendment 2026-08-05, 승제 승인)*

디렉터는 적 **구성**뿐 아니라 적 **성능**도 조정한다. 플레이어가 잘하는 축을 골라 그 축을 무력화하는 것이 목적이다.

**어휘**: `buff` 필드 1개 — 아래 10종 enum 중 하나(성능 7종 + 행동 3종, §3.4.2·§3.4.3). 수치는 LLM이 정하지 못한다(권한 경계 원칙 유지).

| 카드 | 효과 | 노리는 습관(로그 지표) |
|---|---|---|
| `NONE` | 없음 | — |
| `TOUGH` | 전 적 HP +1 (분열 소형 제외 — 소형은 항상 HP 1) | 명중률 높음 (`combat.accuracy`) |
| `SWIFT` | 전 적 이속 +25% | 거리를 벌리며 지연 (`clearTimeSec` 김) |
| `RELENTLESS` | chaser 이속 +45%, chaser HP −1(최소 1) | 대시 남용 (`movement.dashCount`) |
| `RAPID_FIRE` | shooter 발사 간격 ×0.6 (1600→960ms) | 탄을 잘 피함 (`hpLost` 낮음) |
| `MARKSMAN` | shooter 탄속 +50%, 유지거리 +80 (260→340) | 원거리 안전지대 사용 (`wallHugRatio` 낮음) |
| `VOLATILE` | splitter 분열 소형 2→3기 | 물량 처리 능숙 (`combat.kills.splitter`) |
| `INTERCEPT` | 추격형이 현재 위치가 아니라 **예측 지점**으로 이동(선행 = 도달시간, 상한 1.5초 — §3.4.2) | 키팅으로 적을 뭉쳐 쓸어담음 (`combat.clusterRatio` 낮음) |
| `ENCIRCLE` | 추격형이 직진 대신 **포위 반경으로 흩어져** 조여듦 | 한 덩어리 수렴을 이용 (`combat.clusterRatio` 낮음) |
| `EVASIVE` | 전 적이 **좌우로 흔들며 접근**해 자동 조준탄을 흘림 | 가만히 서서 자동 사격으로 녹임 (`combat.accuracy` 높고 `hpLost` 낮음) |

**적용 순서**: `ENEMY_DEF` 기본값 → elite 배수 → 강화 카드. 단 splitter 분열 소형은 `hpOverride: 1`로 스폰되어 HP 버프를 받지 않는다(이속 버프는 받는다). 카드 비용을 소형까지 강화되는 것을 전제로 매기지 않았고, 걸리면 splitter 중심 웨이브의 난이도가 급등하기 때문이다 — 2026-08-05 전체 리뷰에서 확인·의도로 확정. 예) elite chaser HP = 2×3=6, `TOUGH` 적용 시 7. 이속은 elite 1.15 × `SWIFT` 1.25 = 1.4375배.

**밸런스 규칙 (검증 계층이 강제, 위반 시 폴백)**:
1. **웨이브당 1장.** 웨이브 1(오프닝)은 항상 `NONE`.
2. **비용 = 해당 웨이브 예산의 25%(반올림)**, `NONE`은 0. 예산 총액에 합산되므로 강화하면 물량이 줄어든다 — 자동 트레이드오프.
3. **직전 웨이브와 동일한 카드 금지**(`NONE` 제외). 동일 시 `NONE`으로 강제 교체 — mutation과 같은 규칙.
4. **웨이브 종료 시 초기화.** 절대 누적되지 않는다 — 누적이 밸런스 폭주의 주원인이다.
5. 폴백 뱅크 19항목은 전부 `NONE`이다. 폴백은 "디렉터의 판단이 부재한 상태"이므로 강화 없음이 의미론적으로도 맞고, 기존 예산 검증을 건드리지 않는다.

**설계 의도**: `RELENTLESS`처럼 **강해지는 대신 약해지는 축**을 섞는다. 압박은 커지되 클리어 불가능해지지 않게 하는 장치다.

**시스템 프롬프트**: 위 카드↔지표 대응표를 프롬프트에 넣어, 디렉터가 로그에서 관찰된 강점을 근거로 카드를 고르고 `intent`에 그 이유를 쓰게 한다. taunt도 그 강점을 지목해야 한다.

### 3.4.2 행동 카드와 핫스팟 용암 — 지배 전략 차단 *(amendment 2026-08-06, 승제 승인)*

**문제**: 추격형(chaser·splitter)이 전부 `moveToObject(플레이어 현재 위치)`로 직진하므로, 스폰 패턴이 `PINCER`든 `RING`이든 **몇 초 뒤 같은 덩어리로 수렴**한다. 플레이어는 한 구석으로 이동해 적을 몰아두고 한 번에 쓸어담으면 된다 — 디렉터가 무엇을 설계하든 같은 전략이 통한다. 이는 게임 난이도 문제가 아니라 **"AI가 나를 공략한다"는 컨셉 자체를 무력화**하는 결함이다(2026-08-06 승제 실플레이에서 발견).

**해법 3축**:

**(1) 행동 카드 2종** — 강화 카드 어휘를 "성능"에서 "행동"으로 확장한다. 비용·2연속 금지·웨이브 종료 초기화는 §3.4.1 규칙을 그대로 따른다.

두 카드 모두 **예측 지점**을 기준으로 움직인다. 선행 시간은 고정값이 아니라 **그 적이 플레이어에게 도달하는 데 걸리는 시간**(`거리 ÷ 자기 이속`, 상한 1.5초)이다 — 멀리 있는 적은 더 앞을 보고 가까운 적은 덜 본다.

```
lead   = min(거리 ÷ 적 이속, 1.5초)
예측점 = 플레이어 위치 + 플레이어 속도 × lead   (아레나 경계로 클램프)
```

- `INTERCEPT`: 예측점으로 직접 이동한다.
- `ENCIRCLE`: 각 적에게 스폰 순서로 균등 분배한 고유 각도 슬롯을 준다. **예측점을 중심으로** 반경 200px의 자기 각도 지점으로 이동하고, 반경을 초당 25px씩 줄여 조여든다. **반경이 60px까지 줄면 포위를 풀고 일제히 돌진한다 — 이때도 목표는 예측점이다.** 현재 위치로 돌진하면 전원이 같은 점으로 수렴해 이 카드가 막으려던 '뒤에 한 덩어리'가 그대로 재현된다(실측: 포위면 3.75 → 1.25).

돌진 전환이 없으면 포위 카드가 오히려 플레이어를 안전하게 만든다 — 링 위에서 멈춘 적은 접촉 판정(플레이어 11 + chaser 14 = 25px) 밖에 대치선을 형성하고, 반경을 접촉 거리까지 낮춰도 원주(2πr)가 적들의 폭보다 좁아 서로 밀어내며 튕긴다. 2026-08-06 실측: 정지 플레이어 기준 접촉 프레임이 카드 없음 1029 대 포위 30(하한 20px)으로, **'가만히 서 있기'가 새 지배 전략이 됐다.**

방향을 급히 꺾으면 빗나가야 한다 — 완벽한 요격이 아니라 페인트가 통하는 수준이 설계 의도다.

**왜 고정 선행이 아닌가** *(2026-08-06 라이브 실측)*: 최초 설계는 고정 0.4초였다. 플레이어 이속 220 대 추격자 90으로 **속도가 2.4배 차이**나기 때문에 0.4초(88px) 앞을 봐서는 아무 효과가 없다 — 실측에서 `INTERCEPT`의 전방성이 −0.89로 카드 없음(−0.91)과 사실상 동일했고, `ENCIRCLE`은 포위면이 8분면 중 **1개**로 완전히 뭉쳐 따라오기만 했다. 도달 시간 기반으로 바꾸자 전방성 −0.75, 포위면 4면으로 개선됐다. 상한을 2.5초로 더 늘리면 과예측으로 빗나가 오히려 거리가 벌어진다(159 → 166) — 1.5초가 실측상 최적이다.

| 방식 | 평균 거리 | 전방성(−1=완전히 뒤) | 포위면(8분면) |
|---|---|---|---|
| 카드 없음 | 207 | −0.91 | — |
| 고정 0.4초 | 175 | −0.89 | 1 |
| **도달시간 기반(상한 1.5초)** | **159** | **−0.75** | **4** |

*위 표는 **선행 공식을 고르기 위한 비교 실험**이다(프로토타입 패치로 상한값만 바꿔 측정). 수정을 반영한 뒤의 **최종 카드별 성능**은 별도 실측이며 수치가 다르다 — `docs/verification/2026-08-06-behavior-cards-live.md`의 3차 표를 보라. 기술문서가 인용하는 것은 그 최종 수치다.*

**(2) 핫스팟 용암 `LAVA_HOTSPOT`** *(변주 enum 7→8)*: 플레이어가 그 웨이브에서 **가장 오래 머문 지점**에 반경 120px 원형 용암을 깐다. 피해는 기존 용암과 동일(0.5 HP/s).

- **좌표는 디렉터가 정하지 않는다.** 디렉터는 `LAVA_HOTSPOT`이라는 어휘만 고르고, 실제 좌표는 엔진이 텔레메트리 히트맵에서 결정론적으로 계산한다. LLM이 "저기를 태워라"라고 수치를 부르는 게 아니라 "쟤 자리를 태워라"라는 **의도**만 말하고 엔진이 집행하는 구조 — §3.4 권한 경계 원칙이 그대로 지켜진다.
- 로그에 좌표를 **넘기지 않는다**. 넘길 이유가 없고, 넘기면 LLM에게 수치 권한을 주는 셈이 된다.
- 기존 `LAVA_LEFT`/`RIGHT`는 "화면 절반 차단"이라는 다른 역할로 유지한다.

**(3) 판단 근거 지표 2종** — 카드를 만들어도 디렉터가 언제 쓸지 모르면 소용없다.

- `combat.clusterRatio` (0~1): 활성 적들의 중심점 대비 평균 거리를 아레나 대각선 절반으로 정규화해 매 틱 샘플링한 평균. **낮을수록 적이 뭉쳐 있었다** = 몰아서 쓸리고 있다.
- `movement.hotspotConcentration` (0~1): 히트맵 최다 셀의 체류 시간 비율. **높을수록 한 자리에 오래 있었다.**

**시스템 프롬프트 대응**: `clusterRatio`가 낮으면 `INTERCEPT`/`ENCIRCLE`을, `hotspotConcentration`이 높으면 `LAVA_HOTSPOT`을 고르도록 지시하고, 그 근거를 `intent`에 쓰게 한다.

**구현 우선순위**: `INTERCEPT` → `LAVA_HOTSPOT` → `ENCIRCLE`. 앞의 둘만으로도 지배 전략은 깨진다. `ENCIRCLE`이 구현이 가장 무거우므로 마감 압박 시 첫 컷 대상이다.

### 3.4.3 업그레이드 봉인과 회피 기동 — 성장 곡선 대응 *(amendment 2026-08-06, 승제 승인)*

**문제**: 업그레이드를 공격 위주로 6회 고르면(데미지 2·연사 2·멀티샷 2) 초당 피해가 3.6에서 **44.5로 12배**가 된다. 웨이브 5 예산(28)은 1.3초, 웨이브 7 예산(60)은 2.5초면 전멸한다. **자동 조준·자동 사격이라 조작이 필요 없으므로, 5웨이브부터는 가만히 서 있어도 클리어된다**(2026-08-06 승제 실플레이). 예산 곡선이 플레이어 성장을 따라가지 못하는 것이 근본 원인이고, 디렉터는 `upgrades` 로그를 받으면서도 그것에 손쓸 수단이 없었다.

**(1) 업그레이드 봉인 `deny`** — 디렉터가 **플레이어의 성장 경로**를 설계에 넣는다.

디렉티브에 `deny` 필드 1개를 추가한다. 다음 인터벌의 3택1 후보 풀에서 **그 업그레이드 1종을 제외**한다.

- 어휘: `NONE` + 업그레이드 8종 = 9종 enum. 계약이 SSOT이며 `UPGRADE_IDS`와 항목이 일치해야 한다(테스트가 드리프트를 막는다).
- **웨이브 1은 항상 `NONE`**(오프닝 — 로그가 없다).
- **직전 웨이브와 동일한 봉인 금지**(`NONE` 제외). 같은 것을 계속 막으면 그 업그레이드를 영영 얻을 수 없다 — mutation·buff와 같은 규칙으로 검증 계층이 `NONE`으로 강제 교체한다.
- **예산을 소모하지 않는다.** 봉인은 적을 강하게 하는 게 아니라 플레이어의 최적 경로를 막는 것이라 스폰 비용과 축이 다르다. 8종 중 1종만 빠지므로 선택지는 여전히 3개이고 빌드가 봉쇄되지 않는다.
- 폴백 뱅크 19항목은 전부 `NONE`이다(디렉터의 판단이 부재한 상태).
- 프롬프트: 로그의 `upgrades`에서 **반복 선택된 축**을 읽어 그것을 봉인하고, `taunt`가 그 사실을 지목하게 한다("화력만 올리는군. 그 길은 막았다").

**(2) `EVASIVE` 카드** — 자동 사격을 무력화한다.

전 적이 플레이어를 향해 접근하되 **좌우로 흔들며** 온다. 발사 시점에 조준된 위치에서 벗어나므로 자동 조준탄이 빗나간다.

```
이동각 = 플레이어 방향각 + sin(시각/200 + 각도슬롯) × 0.9rad
```

적마다 각도 슬롯(`ENCIRCLE`과 공유)으로 위상이 달라 서로 다른 궤도를 그린다. 접근 자체는 계속하므로 무한 회피가 아니며, 플레이어가 위치를 바꿔 각을 만들거나 멀티샷·관통으로 대응할 수 있다. 비용·2연속 금지·웨이브 종료 초기화는 §3.4.1 규칙을 따른다.

**설계 의도**: 두 수단은 서로 다른 축을 친다. 봉인은 **성장**을, `EVASIVE`는 **조작 불필요**를 겨냥한다. 예산 곡선 상향은 마지막 수단으로 남긴다 — 그것은 밸런싱이지 디렉터의 판단이 아니기 때문이다.

**워밍업 호출** *(amendment 2026-08-05 — 승제 승인)*: 타이틀 화면 진입 시 프록시에 디렉티브 요청 1회를 미리 발사한다. 응답은 버린다.
- **이유**: 하루 첫 호출은 API의 최초 스키마 컴파일 비용과 Edge Function 콜드스타트가 겹쳐 4초 타임아웃을 넘길 확률이 높다. 하필 그 호출이 웨이브 1→2 인터벌 — 게임의 핵심(디렉터가 내 플레이를 읽는 첫 순간)이라, 심사자가 한 판만 플레이하면 LLM 경로를 한 번도 보지 못할 수 있다.
- **동작**: 타이틀에서 비동기 발사 후 결과를 기다리지 않는다(플레이어는 즉시 시작 가능). 실패해도 무시 — 게임 흐름에 어떤 영향도 주지 않는다.
- **캡**: 워밍업은 세션 호출 상한(20)에 **산입하지 않는다**. 일일 예산 캡에는 산입한다.
- 4초 타임아웃 값 자체는 변경하지 않는다.
